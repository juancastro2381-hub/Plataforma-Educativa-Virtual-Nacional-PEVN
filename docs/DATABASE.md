## 2. Database Security Model

### 2.1 User Hierarchy

The database has two users:

| User | Role | Privileges | Used by |
|------|------|-----------|---------|
| `pevn_admin` | Admin | CREATEDB, SUPERUSER | Docker setup, Alembic migrations |
| `pevn_app` | Application | SELECT, INSERT, UPDATE, DELETE only | Running FastAPI application |

**The running application MUST NEVER use the admin user.**

### 2.2 Least Privilege Application User

The `pevn_app` user is created by `infrastructure/docker/postgres/01-init-app-user.sh` with:
```sql
CREATE ROLE "pevn_app" WITH LOGIN PASSWORD '...'
    NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION;

GRANT CONNECT ON DATABASE "pevn_db" TO "pevn_app";
GRANT USAGE ON SCHEMA public TO "pevn_app";
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO "pevn_app";
REVOKE CREATE ON SCHEMA public FROM "pevn_app";
```

The `CREATE` privilege is explicitly revoked — the application cannot create or drop tables. Only migrations (run by the admin user via Alembic) can modify the schema.

### 2.3 Production Database Security Recommendations

- [ ] Enable SSL/TLS for all connections (`sslmode=require` or `sslmode=verify-full`)
- [ ] Run PostgreSQL on a private network not accessible from the public internet
- [ ] Enable PostgreSQL audit logging (`pgaudit` extension)
- [ ] Set up regular automated backups with encrypted storage
- [ ] Use PostgreSQL Row-Level Security (RLS) for fine-grained institutional isolation (Phase 4)
- [ ] Monitor for slow queries and unusual access patterns
- [ ] Rotate database passwords regularly using the secret management system
- [ ] Use connection pooling (PgBouncer) in front of PostgreSQL for production scale

## 3. Connection Configuration

### 3.1 SQLAlchemy Pool Settings

| Parameter | Development | Production Recommendation |
|-----------|------------|--------------------------|
| `pool_size` | 10 | 10-20 |
| `max_overflow` | 20 | 20-40 |
| `pool_timeout` | 30s | 30s |
| `pool_recycle` | 30min | 30min |
| `pool_pre_ping` | True | True |
| `command_timeout` | 60s | 30s |

`pool_pre_ping=True` validates connections before use, detecting stale connections from network interruptions.

### 3.2 Connection String Format

```
postgresql+asyncpg://<user>:<password>@<host>:<port>/<database>
```

Example (development):
```
postgresql+asyncpg://pevn_app:change_me@localhost:5432/pevn_db
```

**SECURITY:** The connection string contains credentials. Never log the raw `DATABASE_URL`. Use `settings.get_safe_database_url()` which masks the password.

## 4. Migration Management

### 4.1 Alembic Configuration

Alembic is configured in `backend/alembic.ini` with:
- `script_location = migrations`
- `prepend_sys_path = .` (allows importing `app.*` modules)
- Async engine via `async_engine_from_config` in `migrations/env.py`

### 4.2 Running Migrations

From the `backend/` directory:

```bash
# Apply all pending migrations
alembic upgrade head

# Create a new migration (autogenerate from model changes)
alembic revision --autogenerate -m "add_user_table"

# Downgrade one migration
alembic downgrade -1

# Show current migration state
alembic current

# Show migration history
alembic history
```

### 4.3 Migration Best Practices

1. **Always review autogenerated migrations** before applying them — Alembic may not detect all changes correctly
2. **Test migrations on a copy** of the database before applying to production
3. **Write rollback steps** for every forward migration
4. **Never modify** an already-applied migration — create a new one
5. **Run migrations in a separate step** from application deployment

### 4.4 Model Registration

For Alembic autogenerate to detect model changes, all domain models must be imported in `app/db/base.py` under the model registry section:

```python
# In app/db/base.py:
from app.models.user import User          # noqa: F401
from app.models.institution import Institution  # noqa: F401
```

This ensures `Base.metadata` contains all table definitions.

## 5. Base Model

All domain tables inherit from `app.db.base.Base` which provides:

| Column | Type | Default | Description |
|--------|------|---------|-------------|
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `NOW()` | Record creation time (set by DB) |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | `NOW()` | Last update time (updated by DB) |

## 7. Naming Conventions

| Element | Convention | Example |
|---------|-----------|---------|
| Table names | `snake_case`, plural | `users`, `institutions` |
| Column names | `snake_case` | `first_name`, `created_at` |
| Primary keys | `id` (UUID) | `id uuid DEFAULT gen_random_uuid()` |
| Foreign keys | `<table>_id` | `institution_id`, `user_id` |
| Indexes | `ix_<table>_<column>` | `ix_users_email` |
| Unique constraints | `uq_<table>_<column>` | `uq_users_email` |
| Check constraints | `ck_<table>_<rule>` | `ck_users_cedula_format` |
